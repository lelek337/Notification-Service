# Микросервис 2: Notification Service

Микросервис для приема событий из Kafka (SMS, Email, Push, Telegram), их дедупликации и последующей пакетной обработки с настраиваемым интервалом.

## Назначение

- Принимать события из отдельных Kafka-топиков.
- Исключать дубликаты по уникальной паре \(key + value\).
- Сохранять входящие сообщения в соответствующие inbox-таблицы.
- Пакетно обрабатывать непрочитанные записи с контролем попыток и логированием.

---

## Структура БД

Каждая сущность хранится в своей таблице inbox. Базовая структура одинакова:

- `id` — UUID, первичный ключ
- `create_at` — TIMESTAMP, дата создания (по умолчанию now)
- `topic` — VARCHAR, топик источника
- `key` — VARCHAR, ключ сообщения
- `value` — TEXT, полезная нагрузка (payload)
- `processed` — BOOLEAN, флаг обработки
- `attempt` — INTEGER, счетчик попыток обработки

### Таблицы

- `sms_inbox` — сообщения из топика `sms-events`
- `email_inbox` — сообщения из топика `email-events`
- `push_inbox` — сообщения из топика `push-events`
- `telegram_inbox` — сообщения из топика `telegram-events`

---

## Интеграции

### Kafka Consumers

- Отдельный Listener под каждый топик:
    - `sms-events`
    - `email-events`
    - `push-events`
    - `telegram-events`

- Каждый Listener:
    - Проверяет уникальность сообщения по паре \(key + value\).
    - Сохраняет запись в соответствующую таблицу `*_inbox`.
    - При дубликате — пропускает обработку (без ошибок, с информативным логом).

---

## Шедулер обработки

- Для каждой таблицы `*_inbox` — отдельный шедулер.
- Интервал запуска настраивается через конфигурацию.
- Поведение шедулера:
    1. Выбирает до \(N\) записей, где `processed = false`, сортировка по `create_at ASC`.
    2. Логирует обработку:  
       `Обработано событие: Key: <key>, Payload: <value>, topic: <topic>`
    3. При успешной обработке — устанавливает `processed = true`.
    4. При ошибке — увеличивает `attempt` на 1, запись остается не обработанной.

_Замечание_: допустимо реализовать обработку в транзакции с оптимистичной блокировкой или `SELECT ... FOR UPDATE SKIP LOCKED` для горизонтального масштабирования воркеров.

---

## Конфигурация

Файл: `application.yml`

```yaml
inbox:
  batch-size: 50     # максимальный размер пачки обработки за один цикл
  delay-ms: 1000     # задержка между запусками шедулера (per inbox)
kafka:
  bootstrap-servers: localhost:9092
  consumer:
    group-id: notification-service
    auto-offset-reset: latest
    enable-auto-commit: false
```

- `inbox.batch-size` — количество сообщений, выбираемых каждым шедулером за один проход.
- `inbox.delay-ms` — задержка между тиками каждого шедулера.
- Параметры Kafka зависят от окружения; рекомендуется ручной коммит оффсетов после успешной записи в БД.
